# Manual acceptance and pilot evidence plan

Automated rendering, interaction, accessibility and contract tests are necessary but insufficient. This plan records the outstanding human evidence without claiming it has run.

| Evidence | Participants/reviewers | Minimum tasks | Exit |
| --- | --- | --- | --- |
| Moderated usability | candidate, recruiter, coordinator, manager, interviewer, approver, support, privacy/HRIS/admin representatives | apply/recover; triage; publish block; schedule/cancel; blind/submit scorecard; decide; approve supersession; handoff failure; privacy request; automation replay; build/restate report | critical journeys completed; severity-ranked findings owned; comprehension meets approved threshold |
| Manual accessibility | keyboard-only, VoiceOver/Safari, NVDA/Firefox or approved equivalents, zoom/reflow and reduced motion | all 14 screen families plus representative object List/New/Detail/Edit and report flow | no critical/serious issue; focus, names, errors, tables/charts and status announcements accepted |
| Content/legal/privacy | HR, employment counsel, privacy, accessibility/content design | candidate statuses, notices, consent, pay/location, rejection/withdrawal, accommodation, privacy, offer and failure/recovery language | versioned inventory and dated approval for pilot jurisdictions |
| Security | security architect/tester | architecture/data flow/threat review; identity/authorization; file; provider; export; logging; incident/cutover | no open blocker/high risk without valid exception; negative evidence stored |
| Pilot rehearsal | named pilot operators and support/on-call | training, one-job dry run, workload/fallback, incidents, rollback/restore and exit | signed go/no-go with all gates and residual risks |

Evidence records must include date, environment/build, scenario, persona, assistive technology/device where relevant, result, artifacts, severity, owner, due date and approver. Status is **not run** until those records exist.
